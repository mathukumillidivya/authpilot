Prior authorization in seconds, with the evidence attached

Before an MRI, a device or a surgery, an insurer checks the request against its coverage rules. It usually takes days. Here a team of AI agents reads the request, applies the real Medicare policy, checks each rule against the patient's record, and quotes the record for every finding. Code verifies every quote, does the date arithmetic and makes the final call.

    How the design got here

    Five rounds on 100 development cases. The first multi-agent design was worse than a single call. Reading its failures changed the design each time.

      What these results do not show

      • The cases are constructed. There is no public benchmark for prior authorization, so the test cases were generated with known answers from real Medicare rules. Real requests are messier: scanned faxes, missing pages, conflicting notes.
      • The records are synthetic and short. About 70 entries per patient. Real charts can run to thousands of pages.
      • Some rules were refined after development review. Three case templates were ambiguous and were rewritten before the test, and two kinds of check (dates, covered procedure codes) were moved into code. The held-out test was run once, after that.
      • Five policies, one model. Results may differ for other services and other models.
      • A human makes the final call on denials. This is decision support, not an automated denial system.
      Policies: Medicare NCD 240.2, 100.1, 20.4; LCD L33718, L33822, L33797.

      Let the model read. Let code count.

      Each step is a node in a LangGraph graph. Purple steps are plain code; blue steps are AI agents. The patient record is reached through an MCP server in front of a FHIR store, the way an agent would reach a hospital's records.

      AI agentIntake

      Reads the provider's request form and pulls out the member, service, code, diagnosis and date.

      Code, then AIPolicy

      Finds the coverage policy by procedure code; an agent routes anything the codes do not settle.

      Code + MCPRecord

      Fetches the chart over MCP in date order, each entry marked with its days before the order.

      AI agents, in parallelSpecialists

      One per coverage rule. Each reads the whole record, judges one rule and quotes its evidence. They share one cached copy of the record.

      CodeVerify

      Checks every quote against the record, checks time windows and covered codes, sends a failed date back to the specialist once, and computes the decision.

      AI agent with toolsInvestigator

      When a rule is undocumented, searches the record again through MCP tools before a second look.

      AI agentLetter

      Writes the determination letter from verified findings only.

      Why not one big prompt?

      • Focus. A specialist judges one rule at a time. The single call had to juggle all of them and mixed them up, for example confusing open and laparoscopic banding.
      • Arithmetic. Models misjudge date windows. Code gives every record its day count and re-checks every time window.
      • Accountability. No finding counts unless its quote matches the record. A denial without verified evidence is impossible by construction.
      • Recovery. When something is undocumented, an investigator searches again before the system asks the provider for more.
